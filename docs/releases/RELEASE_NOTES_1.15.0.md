# Evalanche v1.15.0 — Remote signer

An agent can run Evalanche with no private key in its process. A separate signer holds the key and signs only after an Ed25519 verifier approval.

## Highlights

- Add a pluggable signer so an agent can sign without a local private key in the Evalanche process.
- Add an HTTP(S) and unix-socket remote signer client with bearer auth, request ids, timeouts, and a check that the returned signed transaction decodes to the requested fields.
- Add `evalanche-signer`, a reference server that verifies the pinned verifier key, binds the approval to the exact transaction, and enforces an allow map, calldata checks, nonce state, expiry, SpendingPolicy, token caps, and simulation.
- Fail closed, with a typed `EvalancheError`, on paths that still need raw key material: the Polymarket CLI (`POLYMARKET_PRIVATE_KEY`) and Avalanche X/P-chain / `platform-cli` signing. Read-only tools work from an address alone.
- Harden remote signer approvals, calldata checks, and nonce state. The approval signs `evalanche-verifier/v1`, the decision, dry-run or live mode, the signer address, the chain id, and the intent hash. The intent binds the transaction object. Known calldata is decoded and unknown selectors are denied. A non-empty allow map is required. The nonce file is created only with `--init-nonces`, then locked and fsynced.
- Replace the runtime flock compiler with a pinned Linux helper. Darwin takes the same exclusive lock with `O_EXLOCK` (`0x20`). Exec the pinned lock helper from its checked descriptor. If that helper exits, the signer stops and exits non-zero. Rebuild it with the pinned Ubuntu 24.04 GCC 13.3 recipe. The first Li.Fi leg must set `requiresDeposit`, and later legs must not. Allow entries carry `dex`, `spender`, `recipient`, `token`, and `vault` roles, and roles are additive. A native send requires the `recipient` role. A token address cannot be `callTo`. Config and key files stay root-owned; state directories are owned by the signer user at mode `0700`.
- Record the accepted root risk for TM-008. On the production box the verifier agent holds the wallet key, so separation of duties between key-holder and verifier is gone. The signer enforces policy against mistakes and bad inputs, and it is not a boundary against root. Review date 2027-01-16.
- Document the Grok Bot box signer launch. The host is Linux x86_64. The signer reads `EVALANCHE_SIGNER_PRIVATE_KEY` and then removes it from the environment. It also removes `EVALANCHE_SIGNER_TOKEN`.
- Default the Grok Bot signer to dry-run. `start --live` is the live switch, and a config `dryRun: true` cannot be cleared. `/health` reports `dry-run` or `live`. Start removes a stale socket, uses setsid, and writes the pidfile only after the new process answers health. Stop checks the pid command line and uid and exits non-zero if that process is still alive. The bearer token is a persistent root-owned file. `init` passes `--init-nonces`. Signer checks also run on Node 20.19.2.
- Stop a running Grok Bot signer when the pidfile is missing, stale, or a zombie. Halt the signer before close so a held connection gets 503 and no signature. Serialize start with flock and keep only that child's pid. Ignore `EVALANCHE_BOX_*` overrides when the script runs as root. Read the signer uid once from proc status. Record proposed exit triggers pending owner confirmation. Review date 2027-01-16.
- Provision signer state under the persistent home. On a Grok Bot box, `/etc`, `/opt`, and `/var` do not persist across a reset. `grok-bot-signer.sh provision` is idempotent: it recreates the signer user, reuses an existing uid, reuses the existing evalanche-signer group gid, restores directory modes, and installs the pinned tarball. The nonce store, audit log, verifier key, token, config, and pinned tarball stay under `/home/box/agent-data/evalanche-persist` with the same root-only ownership checks. Re-run provision, then start, after a reset. Do not re-run init when the nonce file is already there.
- Reuse the persistent signer state on reprovision. Every state path stays configurable, and the documented Grok Bot default is `/home/box/agent-data/evalanche-persist`. `provision` recreates the user, `/opt`, and `/etc` from that directory. It does not regenerate a verifier key or reset a nonce file that already exists, so the nonce high-water mark, the audit chain head, and the verifier pubkey are unchanged. There is no boot hook. Re-run provision by hand.
- Refuse a verifier private key on disk. The signer reads only verifier.pub. The approval private key is the bot secret OPS_VERIFIER_ED25519. `provision` exits non-zero when verifier.key is present.
- Match the TM-008 approval key to the bot secret. The approval private key is OPS_VERIFIER_ED25519. Only verifier.pub stays on disk, and provision refuses verifier.key. TM-008 still records that the verifier agent holds the wallet key and that the signer is not a boundary against root. Owner Giacomo Barbieri, decision 2026-10-16, review 2027-01-16.
- Leave trustAnchor unset in production. The bind-mount layout already places nonce and audit under root-owned parents.
- Document approve operating rules for live swaps. Approve only right before the paired swap, for exactly fromAmount. Reset the allowance to 0 if the swap fails. Sweep diamond allowances periodically. The signer does not enforce that pairing.
- Pick a free signer group gid in the reset test. The live box uses 996, and a runner that already has that gid still checks that provision reuses the group it finds.
- Keep node visible when the reset test hides /opt. The runner node under /opt/hostedtoolcache stays on PATH after that mount.
- Claim signer paths through a no-follow file descriptor. `provision` fchowns and fchmods each path it opened with O_NOFOLLOW, so a symlink swapped in after the check is not followed.
- Reuse the existing evalanche-signer uid. A user that already exists, including uid 996, is kept. A missing user gets the first free system uid. `provision` checks that the nonce file owner is that uid.
- Close the start lock before the sudo launcher. The launch closes fd 9 before sudo and before the daemon, so a second start refuses while a signer is running instead of blocking on the flock.
- Build a single-step Kyber Li.Fi route. The proposer fetches the KyberSwap aggregator route and build, with the diamond as sender and recipient, and wraps one `0x4666fc80` call. `quotedAmountOut` is Kyber's amountOut and minOut applies the bought-token class cap. The Li.Fi fixed-fee step stays off the allowlist.
- Reuse the existing evalanche-signer group gid. `provision` does not hardcode gid 960. A group that already exists, including gid 996, is kept, and the signer user's primary gid is checked against it.
- Apply Avalanche slippage classes to USDC and sAVAX. USDC is 50 bps. WAVAX, BTC.b, WETH.e, and sAVAX are 200 bps. Those addresses apply without a config list. Every other token stays at 300 bps.
- Reject trailing bytes on outer Li.Fi V3 calldata. `0x4666fc80` and `0x5fd9ae2e` must re-encode to the same bytes. Extra bytes after the ABI payload are denied.
- Match Kyber srcReceivers to decoded pools. An address appended to the executor calldata, including at an unaligned offset, is not a pool. The zero address is not a pool. A real quote whose pool sits in the decoded swap array still passes.
- Deny Kyber router selectors other than swap. `swapSimpleMode`, `swapGeneric`, empty calldata, and trailing bytes are denied. `callTarget` must be an allowed executor. `srcReceivers` must be that executor or a pool named in its calldata. Fee amounts must be zero.
- Require quotedAmountOut on Li.Fi V3 swaps. A missing quote is denied. minOut must be at least quotedAmountOut times one minus the slippage cap, and the quote must leave a positive token-unit floor. A quote of 1 does not sign. A quote above the bought-token cap is denied.
- Run the signer cli with the pinned node. `npm ci` does not link `evalanche-signer` into `node_modules/.bin`. `start` runs the node path recorded in `node.path` against `dist/signer/cli.mjs`.
- Install the pinned signer tarball with npm ci. `provision` requires the release sha256, copies the tarball into `/var/lib/evalanche-signer` before hashing, and installs that same copy. `npm-shrinkwrap.json` locks ethers, viem, and hyperliquid so a reinstall does not float the ranges in package.json.
- Gate destructive signer reset tests behind `EVALANCHE_DESTRUCTIVE_TESTS`. The default suite does not run sudo, unshare, or userdel. CI sets the variable. The reset test still bind-mounts over the home directory only when that variable is set, and a root start still expects the bind-mount refusal.
- Bind-mount persistent signer state and reassert ownership. A reset restores `/home/box/agent-data/evalanche-persist` as uid 1000. `provision` chowns and chmods that tree on every run and fails closed when the owner or mode does not stick. `start` refuses a box-owned key, nonce, or config. State and log are bind-mounted onto `/var/lib/evalanche-signer/state` and `/var/lib/evalanche-signer/log`, whose parents are root-owned. A `trustAnchor` stops state-path parent checks at a root-owned directory. Symlinks on the path are still refused. The ownership test runs the signer script from outside the home directory.
- Set the Li.Fi integrator fee to zero and allow exchanges from config. Quote and route requests send integrator `evalanche` and `fee` 0, so an integrator fee cannot add a FeeForwarder step. `allowExchanges` defaults from config. The Grok Bot proposer can limit routes to `kyberswap`.
- Reject a zero Li.Fi V3 minOut and decode Kyber receivers. A V3 `minAmountOut` of zero is denied. When the intent carries `quotedAmountOut`, minOut must cover that quote after slippage: `quotedAmountOut * (10000 - bps) / 10000`. `bps` is `maxSlippageBps` when set, otherwise the bought-token class cap. Those caps default to 50 bps for stables, 200 bps for top assets, and 300 bps for every other token, and `maxSlippageBps` above the class cap is denied. A Kyber MetaAggregationRouterV2 `swap` (`0xe21fd0e9`) inside a V3 leg is decoded. Its destination token must be the leg's token-out. Its dst receiver must be the Li.Fi diamond on an intermediate leg, or the diamond or an allowlisted recipient on the last leg. Kyber calldata that cannot be decoded is denied. An approve of zero to an allowlisted spender still signs, so a failed swap can reset its allowance. Approve and the swap stay separate requests.
- Decode Avalanche Li.Fi V3 swap selectors. On Avalanche the diamond facet lookup returns the zero address for `swapTokensGeneric` (`0x4630a0d8`). GenericSwapFacetV3 `0x31a9b1835864706Af10103b31Ea2b79bdb995F5F` serves `swapTokensSingleV3ERC20ToERC20` (`0x4666fc80`) and `swapTokensMultipleV3ERC20ToERC20` (`0x5fd9ae2e`). Every leg is decoded. Approve spenders and inner call targets are checked against the role allowlist. The receiver must have the recipient role and must be the signer wallet. Caps price the sold asset. `minAmountOut` is enforced. Unknown selectors, including the native V3 selectors, stay denied.
- Bind swap legs to `tokenIn`, `amountIn`, and `tokenOut`, and cap the sold asset rather than the router. Spenders, transfer recipients, and Li.Fi `callTo` / `approveTo` must carry the matching allow role. The first leg must set `requiresDeposit`. Inner multicall selectors are checked the same way. Polymarket typed data, small-order verifier keys, and non-canonical signatures are denied. File checks use `O_NOFOLLOW` and cover parent directories. The default gas cap is about 0.02 native tokens, and `tx.type` must be 0 or 2.

## Install

```sh
npm install evalanche@1.15.0
```

`evalanche-mcp --signer-url` (or `EVALANCHE_SIGNER_URL` plus `EVALANCHE_SIGNER_ADDRESS`) starts the MCP server without loading a key. `evalanche-signer` is the reference process that holds the key.

## What changed

- `EvalancheConfig.signer` accepts a local ethers wallet, a `SigningProvider`, or a `RemoteSignerConfig`. It is mutually exclusive with `privateKey` and `mnemonic`.
- `EvalancheConfig.address` starts an address-only agent. Signing throws `REMOTE_SIGNER_UNSUPPORTED`.
- EVM transaction, message, and EIP-712 signing, including Li.Fi swaps and bridges, vaults, staking, x402, and Hyperliquid typed data, goes through the signer. The reference server decodes known selectors and denies the rest. A Li.Fi swap must bind its legs to the intent, and caps price the sold asset. Hyperliquid and Polymarket typed data are denied by domain and contract. An `approve` amount must equal the decoded `amountIn`, and the spender must be allowlisted. Message and typed-data signing are off unless allowlisted.
- Verifier approvals are `{ intentHash, nonce, expiresAt, verifier, signature, decision, mode, signerAddress }`. `signVerifierApproval` signs `evalanche-verifier/v1`, the decision, the mode, the signer address, the chain id, and the intent hash. Only `approve` is accepted. `routeHash` is `computeApprovedTxHash` of the transaction object. Swap or bridge intents must include a `minAmountOut` bound that the decoded call satisfies.
- The signer binds to `127.0.0.1` or a unix socket, writes an append-only JSONL audit log chained to a fixed root, and can run in dry-run mode. Dry-run consumes the nonce and returns without a signature. `--init-nonces` is required when the nonce file is missing or empty.

## Migration

Local `privateKey` and `mnemonic` configs behave as before. Agents that move to a remote signer must stop passing those fields and must attach a verifier approval to each signature. The signer config must include a non-empty `allow` map. Vault helpers that approve `MaxUint256` are rejected. Li.Fi bridge calls other than `swapTokensGeneric`, the Avalanche V3 selectors `swapTokensSingleV3ERC20ToERC20` and `swapTokensMultipleV3ERC20ToERC20`, and a `multicall` of decoded calls are denied until a decoder exists for them.

Node.js 20 or newer is still required.
