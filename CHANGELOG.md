# Changelog

## 1.17.0-rc.2

- Release candidate. The live box is 1.17.0-rc.1 at `6ad45d8` (`6ad45d810622db13ef1561d9b1f01864d8d78af4`). Provision `evalanche-1.17.0-rc.2.tgz` as a new pin and leave `evalanche-1.17.0-rc.1.tgz` in place. Provisioning again under the rc.1 filename would overwrite the pin a rollback reinstalls.
- Off Avalanche, `buildKyberLifiSwap` and `buildDirectDexSwap` require `slippageCaps` on the request or `signer.slippageCaps` from the signer chain config. A missing list fails closed and names the chain. When the signer caps are set they are the ceiling, so a request that allows more bps than the signer class for that token is refused. A 300 bps default is refused when the signer stable cap is 50 bps. Avalanche still uses the built-in stable and top lists when caps are omitted.
- `quoteDirectDexSwap` quotes Cronos through VVS `getAmountsOut` on the pinned router, and Gnosis and Celo through Uniswap QuoterV2 `quoteExactInput`. Gnosis QuoterV2 is `0x7E9cB3499A6cee3baBe5c8a3D328EA7FD36578f4` (Uniswap governance deployment list, factory `0xe32F7dD7e3f098D518ff19A22d5f028e076489B1`). Celo QuoterV2 is `0x82825d0554fA07f7FC52Ab63c961F330fdEFa8E8` (Uniswap Celo deployments and Celo contract docs, factory `0xAfE208a311B21f13EF87E33A90049fC17A7acDEc`). The hop must be in `dex.pools`. `buildExactRouterApproval` approves exactly `amountIn` to the pinned router. The signer server, its decode path, and the chain defaults are unchanged.

## 1.17.0-rc.1

- Release candidate only. The live Grok Bot box still runs 1.16.0 at `b788bd5` (`b788bd50c2df91eb253d6f61d08847249437811e`) with a multichain config on chains 1, 10, 56, 137, 4663, 8453, 42161, 43114, 59144, and 80094. This rc is not deployed.
- The on-box tarball name comes from `package/package.json` in the staged tarball, after the checksum. It does not come from the installed tree or the working directory. A bad version, or an `evalanche-<version>.tgz` name that does not match, is refused before npm. This package pins `evalanche-1.17.0-rc.1.tgz`. The live 1.16.0 install was provisioned under the previous name. Upgrading the box means running `provision` with the new tarball and its published sha256. As root, `EVALANCHE_BOX_TARBALL` is ignored. `start` does not read `package.json` and does not rename an install that is already on disk.
- Add a CoinGecko `simple/price` source on `price.priceFeed`. It is HTTPS only, on `https://api.coingecko.com/api/v3/simple/price`, mapped by coin id, and fails closed on a malformed, missing, stale, or out-of-range price. Redirects are refused. A feed price must sit inside `price.bounds` or within 50% of a positive static price. Static `price.prices` and `price.sanitySource` still work, and a static price is not a fallback when the feed fails. Switching the live config to `priceFeed` is optional, and only needed when those static prices are dropped.
- Build KyberSwap aggregator routes on every pinned chain where Kyber is available: 1, 10, 56, 137, 146, 999, 4663, 8453, 42161, 43114, 59144, and 80094. Each chain uses its pinned router, Li.Fi diamond, and wrapped native. The builder refuses a disabled chain, an unknown router, a recipient that is not the treasury, and a route that does not match the build. The route-summary and build checks, minOut, and router pin stay in place.
- Add a direct swap venue for Cronos (VVS v2), Gnosis (Uniswap SwapRouter02), Celo (Uniswap SwapRouter02), and Mantle (Agni SwapRouter). Each stays off until `chains[id].dex.enabled` is true, and the chain stays off until `enabled` is true. The signer decodes only the pinned selectors, requires path tokens on the token allowlist, requires the recipient to be the treasury, requires a nonzero `amountOutMin`, and caps the deadline at ten minutes. Multicall is signed only when every inner call passes those checks. Value must be 0. Cronos accepts only `swapExactTokensForTokens`. VVS has no multicall, so both multicall selectors are denied.
- Require `quotedAmountOut` on a direct swap. `minOut` must be at least that quote after the bought-token class slippage, and the quote must sit inside the bought-token cap. A missing quote is denied. An enabled venue also requires `dex.pools` (token pair, plus a fee tier on v3). Every hop must match, including a middle hop. `sqrtPriceLimitX96` must be 0. The liquid allowlist is WCRO/USDC and WCRO/USDT on Cronos, WXDAI/USDC.e fee 100 on Gnosis (`0x2a22f9c3b484c3629090FeED35F17Ff8F88f76F0`), and CELO/USDT fee 100 on Celo. Mantle stays off: the best Agni pool is about $14k TVL. The `poolDepthVerified` guard remains.
- Refuse to start an enabled chain whose direct venue is on unless that chain has a cap for the pinned wrapped native, a cap for every allowlisted token, a native cap, a positive `gas.maxFeeUsd`, and a native price or HTTPS feed. A configured router, wrapped native, or selector that is not the pin is rejected. Mantle 5000 also requires `dex.poolDepthVerified: true` and `dex.verifiedAt` as a `YYYY-MM-DD` date on or before today. Without that acknowledgement startup fails and reports that pool depth must be rechecked first.
- Remove Fantom 250 and zkSync Era 324 from the registry, the signer chain policy, and the SDK and MCP chain lists. Fantom Opera was sunset. zkSync EraVM bytecode cannot be checked against audited EVM bytecode. Chain ids 250 and 324 fail startup as unknown. Transaction type 113 stays denied.
- Add Sonic 146 and HyperEVM 999, both disabled by default. Each uses the pinned Kyber MetaAggregationRouterV2 plus its Li.Fi diamond. Sonic's diamond is the canonical address. HyperEVM's diamond is `0x0a0758d937d1059c356D4714e57F5df0239bce1A`, so `chains.999.lifiDiamond` must be set before a swap. CoinGecko ids are `sonic-3` and `hyperliquid`. `dex.enabled` fails startup on both because no direct venue is pinned.
- Leave Moonbeam, Blast, and Scroll unimplemented. Moonbeam had no confirmed liquid venue. Blast's liquid Thruster router exposes `setManager`, and canonical Uniswap there is not a treasury venue. Scroll's canonical Uniswap is not liquid, and the liquid routers take arbitrary path or callback bytes. `dex.enabled` on any of those chains fails startup. The assessment, addresses, and RPC checks are in `docs/signer-multichain.md`.
- The proposer compares its Kyber pin with the signer config before it builds a route. An omitted `signer.lifiDiamond` is the canonical diamond. Sonic 146 matches. HyperEVM 999 does not, so the builder refuses it until the signer diamond is `0x0a0758d937d1059c356D4714e57F5df0239bce1A`. A router or wrapped native that disagrees with the pin is refused. `buildDirectDexSwap` builds Cronos VVS (`swapExactTokensForTokens` only), Gnosis SwapRouter02, and Celo SwapRouter02 intents from `dex.pools`. Each intent sets `quotedAmountOut` and a minOut at or above the class-slippage floor. `sqrtPriceLimitX96` is 0, value is 0, and the deadline stays inside 600 seconds. Mantle is refused unless `poolDepthVerified` is set. The signer server, its decode path, and the chain defaults are unchanged.

## 1.16.0

- Add a per-chain signer policy for the nineteen mainnets. Avalanche 43114 stays on unless `enabled` is false or `killSwitch` is true. Every other chain stays off until `enabled` is true. Testnets cannot be enabled. An old file with no `chains` object keeps its chain list, shared token caps, gas cap, price source, and Avalanche slippage defaults.
- Price each chain from its own `price.prices` or `price.sanitySource`. The global price map is not applied once `chains` is set. An enabled chain must have a native cap, a cap for every allowlisted token, a positive `gas.maxFeeUsd`, and a native price or HTTPS feed. Address-keyed `tokenCaps` are not copied onto those chains. The native wei gas cap remains. An old file without `chains` still starts with the wei cap and no USD cap.
- Allow CTF `setApprovalForAll` to a current V2 exchange with `approved` false, and `pauseUser()` on the standard and neg-risk V2 exchanges, as kill switches. `unpauseUser` and admin `pauseTrading` stay denied.
- Stop adding the ERC-20 `transfer` selector when the Avalanche LP module is enabled. A transfer selector already in the allow map stays. The position manager is module-handled only while that module is on. A zero approve to the position manager is allowed so an allowance can be revoked. `MaxUint256` stays denied.
- Key token caps, RPC lists, gas mode, Li.Fi diamond selectors, Kyber executors, and price feeds by chain. The same token address on two chains does not share a cap. Gas mode is legacy, EIP-1559, or both. zkSync type 113 stays denied. Simulation uses the request chain's RPC list and does not fall through a revert.
- Add a Polymarket module on Polygon 137, off by default. `polymarket-order` signs the V2 Order typehash and requires maker and signer to be the treasury, signature type 0, an allowlisted market, a price inside the mid band, and FOK. The exchange does not sign expiration, nonce, feeRateBps, or taker, so the signer does not enforce them. `clob-auth` and the V3 exchange are separate flags and stay off. CTF `setApprovalForAll` to a current V2 exchange, CTF and NegRiskAdapter redeems, and a zero ERC-20 revoke are the only gated transactions. Split, merge, and positive approvals stay denied. Generic typed data still cannot sign these domains.
- Add an Avalanche Uniswap v3 concentrated-liquidity module, off by default. It allows an exact WAVAX or USDC approve to the NonfungiblePositionManager, plus mint, collect, decreaseLiquidity, and burn on the allowlisted pool. The recipient is the treasury. Deadlines must fall inside ten minutes. NFT transfer and approval selectors stay blocked. `increaseLiquidity` stays blocked unless the config flag is set. A multicall is signed only when every inner call passes the same checks. While the module is on, WAVAX and USDC are added to the 43114 allow map so a swap can fund the position. The Grok Bot provision template is unchanged.

## 1.15.0

- Add a pluggable signer so an agent can sign without a local private key in the Evalanche process.
- Add a remote signer HTTP(S) and unix-socket client. The client sends a canonical signing request and rejects a signed transaction that does not decode to the requested fields.
- Add the `evalanche-signer` reference server. It holds the key, checks an Ed25519 verifier approval, recomputes the intent hash, and enforces a monotonic single-use nonce, expiry, a deny list, SpendingPolicy, token-amount caps, and simulation. Dry-run never signs. Decisions are appended to a JSONL audit log. The default bind is `127.0.0.1` or a unix socket.
- `evalanche-mcp` accepts `--signer-url` / `EVALANCHE_SIGNER_URL` and can run keyless. `EVALANCHE_ADDRESS` is address-only mode.
- Polymarket CLI and Avalanche X/P-chain paths fail with `REMOTE_SIGNER_UNSUPPORTED` when a remote signer or address-only wallet is configured. They do not fall back to an environment private key.
- Harden the remote signer. Approvals bind the full transaction, the decision, and dry-run or live mode. Calldata checks decode known calls and deny the rest. The nonce store must be initialized, is locked and fsynced, and rejects approvals created before its start time. Message and typed-data signing are off unless allowlisted. Permit, Permit2, increaseAllowance, Benqi sAVAX instant unstake, Polymarket, and Hyperliquid typed data are denied. The audit log is a prevHash chain rooted at the SHA-256 of `evalanche-audit-root/v1`.
- Record the accepted root risk for TM-008. On the production box the verifier agent holds the wallet key, so separation of duties between key-holder and verifier is gone. The signer enforces policy and is not a boundary against root. Review date 2027-01-16.
- Document the Grok Bot box signer launch. The signer reads `EVALANCHE_SIGNER_PRIVATE_KEY` and then removes it from the environment. It also removes `EVALANCHE_SIGNER_TOKEN`.
- Default the Grok Bot signer to dry-run. `/health` reports the mode. Start and stop follow the new process. The bearer token is a root-owned file. `init` passes `--init-nonces`. Signer checks also run on Node 20.19.2.
- Stop a running Grok Bot signer when the pidfile is missing. Halt the signer before close so a held connection gets no signature. Serialize start with flock. Record proposed exit triggers pending owner confirmation.
- Provision signer state under the persistent home. `grok-bot-signer.sh provision` recreates the signer user and reinstalls the pinned tarball after a reset. The nonce store, audit log, verifier key, and config stay under `/home/box/agent-data/evalanche-persist`.
- Reuse the persistent signer state on reprovision. `provision` recreates the user, `/opt`, and `/etc` from that directory and does not regenerate keys or reset nonces that already exist. Re-run it by hand. There is no boot hook.
- Bind-mount persistent signer state and reassert ownership. `provision` chowns the persistent tree back from uid 1000 and fails closed if it cannot. State and log are bind-mounted under `/var/lib/evalanche-signer`. A `trustAnchor` can stop state-path parent checks at a root-owned directory.
- Refuse a verifier private key on disk. The approval private key is the bot secret OPS_VERIFIER_ED25519. The signer keeps only verifier.pub.
- Match the TM-008 approval key to the bot secret. Only verifier.pub stays on disk. The acceptance, owner, and 2027-01-16 review are unchanged.
- Leave trustAnchor unset in production. The Grok Bot bind mounts already cover nonce and audit.
- Document approve operating rules for live swaps. Approve only right before the paired swap, for exactly fromAmount. Reset the allowance to 0 if the swap fails, and sweep diamond allowances periodically.
- Pick a free signer group gid in the reset test when 996 is already taken.
- Keep node visible when the reset test hides /opt.
- Claim signer paths through a no-follow file descriptor. `provision` uses fchown and fchmod on that descriptor.
- Reuse the existing evalanche-signer uid instead of pinning uid 960. A missing user gets a free system uid, and the nonce file owner is checked afterwards.
- Close the start lock before the sudo launcher. A second start refuses while a signer is running.
- Build a single-step Kyber Li.Fi route from the KyberSwap aggregator. One GenericSwapFacetV3 call, no Li.Fi fixed-fee step, and minOut from the bought-token class cap. Keep the Kyber route out of the bridge import.
- Match the Kyber route and build to the request. tokenIn, tokenOut, and amountIn must be exact, the router must be the one for the chain, and the build amountOut must be within 0.1% of the route amountOut.
- Refuse a Kyber quote below the reference price. An optional reference amount or fetcher throws when quotedAmountOut is more than 1% below it. The signer does not run the check.
- Remount signer state mounts nosuid, nodev, and noexec. `start` fails closed when a state or log bind is missing one of those flags.
- Set example slippage caps to the Avalanche classes. USDC and USDt are 50 bps, WAVAX, BTC.b, WETH.e, and sAVAX are 200 bps, and every other token is 300 bps.
- Refuse a node binary that is not root-owned, and refuse one whose directory chain is group or world writable.
- Refuse a signer uid outside the system range. `provision` does not reuse uid 0 or a uid below 100 or above 999.
- Document the hyperliquid Node engine warning. `@nktkas/hyperliquid` 0.33.3 asks for Node 22.12, and `npm ci` on Node 20 prints it. The pin stays.
- Reuse the existing evalanche-signer group gid instead of hardcoding gid 960.
- Apply Avalanche slippage classes to USDC and sAVAX. USDC is 50 bps. WAVAX, BTC.b, WETH.e, and sAVAX are 200 bps instead of the 300 bps default.
- Reject trailing bytes on outer Li.Fi V3 calldata. The decoded `0x4666fc80` and `0x5fd9ae2e` payloads must re-encode to the same length.
- Match Kyber srcReceivers to decoded pools. Appended and unaligned addresses, and the zero address, are denied.
- Deny Kyber router selectors other than swap. Executor `callTarget`, `srcReceivers`, and fee amounts are checked. Trailing Kyber bytes are denied.
- Require quotedAmountOut on Li.Fi V3 swaps. A missing or one-unit quote is denied, and the quote must sit within the bought-token cap.
- Run the signer cli with the pinned node. `start` executes `dist/signer/cli.mjs` and does not use `node_modules/.bin/evalanche-signer`.
- Install the pinned signer tarball with npm ci. The sha256 is required, the hashed bytes are the bytes that are installed, and `npm-shrinkwrap.json` locks the dependency tree.
- Gate destructive signer reset tests. `EVALANCHE_DESTRUCTIVE_TESTS` must be set before the suite runs sudo, unshare, or userdel.
- Test signer ownership outside the home directory. The reset test keeps the signer script reachable when `/home` is replaced, and a root start reports the real state bind mount.
- Set the Li.Fi integrator fee to zero and allow exchanges from config. Quotes send `fee` 0 so a FeeForwarder step is not added. `allowExchanges` defaults from config and can limit routes to `kyberswap`.
- Reject a zero Li.Fi V3 minOut and decode Kyber receivers. `quotedAmountOut` sets a slippage floor from the bought-token class cap (stables 50 bps, top assets 200 bps, other tokens 300 bps). A Kyber `swap` (`0xe21fd0e9`) inside a V3 leg must pay the Li.Fi diamond, or an allowlisted recipient on the last leg. An approve of zero still signs so a failed swap can reset its allowance.
- Decode Avalanche Li.Fi V3 swap selectors `0x4666fc80` and `0x5fd9ae2e` on GenericSwapFacetV3 `0x31a9b1835864706Af10103b31Ea2b79bdb995F5F`. `swapTokensGeneric` is not registered on the Avalanche diamond. Every leg is decoded, approve spenders and inner call targets must be allowlisted, the receiver must have the recipient role, caps price the sold asset, and `minAmountOut` is enforced. Unknown selectors stay denied.
- Bind Li.Fi swap legs to the intent and cap the sold asset. Allow entries need `dex`, `spender`, `recipient`, `token`, and `vault` roles, and roles are additive. A native send requires `recipient`. A token cannot be `callTo`. The first swap leg must set `requiresDeposit`. Reject small-order verifier keys, non-canonical signatures, and Polymarket typed data. Open signer files with `O_NOFOLLOW`. Config and keys are root-owned; state directories are owned by the signer user at mode `0700`. Exec the pinned lock helper from its checked descriptor (`O_EXLOCK` `0x20` on macOS). A dead helper stops the signer. Rebuild that binary with the pinned GCC 13.3 recipe. Default the gas cap to about 0.02 native tokens.
